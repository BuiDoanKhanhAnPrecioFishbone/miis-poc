## The 125 % zoom defect this run was written for

Reported against the AI-analysis fields and reproduced by measurement before any fix:

| Width | Header heights in one grid row | Values clipped inside their input |
|---|---|---|
| 1600 sv | 28 px | `matched`, `employeeOrg` |
| **1440 sv** | **28 px and 52 px** | `matched`, `employeeOrg` |
| 1440 en | 28 px and 52 px | `matched`, `employeeOrg` |
| 1024 / 900 / 820 / 700 | 28 and 52 at some widths | `matched`, `employeeOrg` |

Two separate faults. A label that wrapped in one column and not the other made the two
headers different heights, so the inputs beside each other no longer lined up — worse in
English, where the labels are longer. And the two longest values were silently cut off
inside their `<input>`, on the one screen whose entire purpose is checking that the AI
read the right party.

Fixed by giving each field a three-row band that shares the grid's rows
(`grid-rows-subgrid`), so a row is as tall as its tallest label and every input sits on
the same line whatever the language; and by laying the two long fields across the full
width, since no half-column at any real viewport fits them.

Re-measured at 11 widths from 1920 down to 600, in both languages: the number of
distinct input positions now equals the number of layout rows exactly at every width,
and nothing overflows.

| | Before | After |
|---|---|---|
| Widths with misaligned inputs | 1440, 820 (sv) · 1600, 1440, 1024, 900, 820, 700 (en) | none |
| Widths with a clipped value | 6 of 11 | none |
