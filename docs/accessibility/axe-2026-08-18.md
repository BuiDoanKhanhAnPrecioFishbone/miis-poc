## The 125 % zoom defect this run was written for

Reported against the AI-analysis fields and reproduced by measurement before any fix:

| Width | Header heights in one grid row | Values clipped inside their input |
|---|---|---|
| 1600 sv | 28 px | `matched`, `employeeOrg` |
| **1440 sv** | **28 px and 52 px** | `matched`, `employeeOrg` |
| 1440 en | 28 px and 52 px | `matched`, `employeeOrg` |
| 1024 / 900 / 820 / 700 | 28 and 52 at some widths | `matched`, `employeeOrg` |

Two separate faults. A label that wrapped in one column and not the other made the two
headers different heights, so the inputs beside each other no longer lined up — worse in
English, where the labels are longer. And the two longest values were silently cut off
inside their `<input>`, on the one screen whose entire purpose is checking that the AI
read the right party.

Fixed by giving each field a three-row band that shares the grid's rows
(`grid-rows-subgrid`), so a row is as tall as its tallest label and every input sits on
the same line whatever the language; and by laying the two long fields across the full
width, since no half-column at any real viewport fits them.

Re-measured at 11 widths from 1920 down to 600, in both languages: the number of
distinct input positions now equals the number of layout rows exactly at every width,
and nothing overflows.

| | Before | After |
|---|---|---|
| Widths with misaligned inputs | 1440, 820 (sv) · 1600, 1440, 1024, 900, 820, 700 (en) | none |
| Widths with a clipped value | 6 of 11 | none |

## The overflow sweep

Every element on every route was measured for `scrollWidth > clientWidth`, at 7 widths
in both languages, with `.sr-only` excluded — it is clipped to 1px on purpose.

| | Distinct hits |
|---|---|
| Before | 30 |
| After | **2** |

The two that remain are the `<input>`s holding the two longest party names at 375px,
where an input scrolling its own value is ordinary browser behaviour and the viewport is
below any realistic use of a Swedish authority's case tool.

Three of the fixes were one-line and none of them was cosmetic:

**`DataTable` needed `position: relative`.** `sr-only` positions absolutely, and an
absolutely positioned descendant is clipped by `overflow` only when its containing block
is inside the scroller. Without a positioned ancestor, the hidden sort descriptions and
the table caption resolved against the page instead — so **every route with a wide table
gave the whole document a horizontal scrollbar at every width below 1152px**, from
invisible text. `/dokument` was 36px over at 1024 and 228px over at 768.

**Every grid needed an explicit base column.** Tailwind's `grid-cols-N` expands to
`repeat(N, minmax(0, 1fr))`, but a grid whose only column declaration is a responsive
variant has no explicit track at the base width and falls back to one implicit `auto`
column — which is sized by its content's minimum, which a `DataTable` sets. Nine files
had grids in that shape. `grid-cols-1` makes the base track shrinkable.

**`Panel` needed `min-w-0`,** so a panel can shrink below the intrinsic width of a table
inside it rather than being sized to it.

The rest: the uploaded file name is a single unbroken token and set the minimum width of
the whole protocol column (`break-all`), and a `Field` label narrower than its longest
word spilled instead of breaking — *"Diarienummer (diariesystemet)"* is 107px in a 91px
column at 1152 (`break-words`).

## The AI proposal labels

The `AI-FÖRSLAG` pill sat in every field's label row and was wider than most of the
labels it followed, so the row it annotated wrapped. It is now a violet field border
plus a 48px source button beside the input.

Checked against the rules it touches:

| Rule | How it holds |
|---|---|
| 1.4.1 colour is never the only carrier | The border is violet **and** there is a button beside it **and** its accessible name begins with *AI-förslag* **and** the panel states in words what the colour means |
| 4.1.2 name, role, value | The button is a real `<button>` with `aria-pressed` and an accessible name naming its field |
| 2.5.5 target size | 48 × 48, up from a 28px-tall pill |
| CLAUDE.md rule 2 | Violet is AI's alone, so the border cannot be read as an FR-012 status or as an error — an empty required field still takes the error border and wins |
| Our chapter 9 wording | The tender says every proposal is *"clearly labelled (AI-FÖRSLAG)"*. MI's own FAI-002 requires review and approval, not a specific label, so there is latitude — but the phrase is ours and it is in the document MI reads. The words survive in the panel line, in every button's accessible name, and on the `JUSTERAD` chip. **If the tender text is not being changed, this is the one item to look at again.** |
