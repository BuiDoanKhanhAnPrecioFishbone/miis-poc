## Violations found and fixed in this run

Both were found by the run, not by review — which is the argument for running it.

1. **`color-contrast` (serious)** — `text-primary/80` on the mint decision-support panel
   in `/medling/[id]`. Reduced-opacity text was removed everywhere it was used
   (`text-primary/80`, `text-sand-foreground/80`, `text-demo-foreground/80`); the tokens
   are now used at full strength. Opacity is a convenient way to soften text and a
   reliable way to fail 1.4.3.

2. **`scrollable-region-focusable` (serious)** — the protocol pane in `/registrera`
   scrolls, and its content was not focusable, so a keyboard user could not reach the
   lower half of the document. It is now `tabindex="0"` with `role="region"` and the
   file name as its accessible name (2.1.1).

## Manual checks

Automated tooling catches roughly a third of WCAG issues. These were checked by hand:

| Check | Result |
|---|---|
| 200 % zoom (720 px effective width) | No horizontal scrolling; `document.scrollWidth === innerWidth` on every route |
| Responsive (NFUI-002) | Sidebar rail at ≥1024 px, narrow rail 768–1023 px, stacked above content below 768 px. No horizontal overflow at 700, 768 or 1440 px |
| Focus return after a modal | Session-timeout dialog returns focus to the control that opened it |
| Keyboard trap (2.1.2) | Tab is cycled inside the dialog; Escape closes it |
| Colour as the only carrier (1.4.1) | FR-012 status uses colour **and** shape (filled circle / filled square / hollow ring) **and** a visible text label. Legible in greyscale |
| Language of page (3.1.1) | `<html lang>` follows the language switch — `sv` by default, `en` when toggled |
| Requirement-tag toggle | Toggling causes zero layout shift: identical `scrollHeight` and identical element positions on `/` and on `/registrera`, the densest screen |
